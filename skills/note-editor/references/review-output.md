# note-editor 出力フォーマット

findings(category/severity/箇所/問題/改善案)が中身の核。以下は**人向けの体裁**。note-writing ループから
呼ばれたときは「総合判定 + 重大・中の findings(修正案つき)」を中心に簡潔に返し、単体レビュー時は
通常フォーマットで厚めに返す。

## 通常レビュー

### 総評
100〜200字で、記事全体の印象と最大の改善ポイント。

### この記事の芯
- 推定される主張:
- 想定読者:
- 読後に残るもの:
- 1記事1テーマか:

### 良い点
3〜5個。**褒めるだけで終わらない**。

### 大きく直すべき点(= 重大・中の findings)
重要度順に3〜7個。各項目:
- category / severity:
- 問題:
- なぜ問題か:
- 改善案:
- 修正するなら:(必要なら 修正前 / 修正後)

### タイトル案
方向性を分けて5〜10案。各案に**どの読者に刺さるか**を一言。
(結論型 / 体験型 / 悩み寄せ型 / 違和感・発見型 / 少し長いが分かる型)

### 冒頭改善案(必要時のみ)
方向性を分けて複数: 体験から / 問題提起から / 結論から / 違和感から。

### 見出し構成案(必要時のみ)
改善後の見出しツリーを出す。

### スマホ読みチェック
長すぎる文 / 長すぎる段落 / 改行すべき箇所 / 箇条書きにすべき箇所 / 画像・図を入れるべき箇所。

### 文体の具体修正
具体的な文を取り上げ、**修正前 / 修正後 / 意図** の3点で。

### 残した方がいい表現
筆者らしさが出ている表現を挙げ、**安易に整えない方がいい理由**も述べる。

### 公開前チェックリスト
公開前に見るべき項目を短く列挙。

## 簡易レビュー(軽く見てほしい場合)

以下だけ返す:
1. 一番直すべきところ
2. タイトル案3つ
3. 冒頭の改善案
4. 見出しの改善案
5. そのまま残した方がいい表現

## リライト時の方針(ユーザーがリライトを依頼した場合のみ本文を書き換える)

- 筆者の語尾・温度感をできるだけ残す。
- 修正箇所の意図を説明する。全文を均一に整えすぎない。**必要な箇所だけ**直す。
- 情報の追加が必要な場合は「追加提案」として**分ける**(勝手に本文へ混ぜない)。
- 文章を短くするだけでなく、**読み飛ばせる余白**も残す。
