# 画像スタイルのガイド(名前付きスタイルの仕組み・リビング)

サムネ・本文図の**見た目を揃え、"AIっぽさ"を減らす**ための名前付きスタイルの使い方。
**スタイルの実体はリポジトリ直下 `styles/<名前>.yaml`**(1ファイル1スタイル)。ここはその仕組みの説明。
最終更新: 2026-05-30(初版・種)。

## 参照のしくみ

- 記事全体の既定は frontmatter の `image_style: <名前>`。figure ごとに `style: <名前>` で上書きできる。
- 名前は `styles/<名前>.yaml` に対応(例: `style: flat-diagram` → `styles/flat-diagram.yaml`)。
- 各スタイルの **`prompt断片`** を、figure 固有の `prompt` に**連結**して画像生成へ渡す(画像ツール非依存・日本語)。
- サムネと本文図を同じスタイル名にすると、記事・一覧での統一感が出る。
- 無指定だとスタイル無しで生成され**ばらつく**(かつ後述の"AIっぽさ"が出やすい)。揃えたいなら必ず名前を指定。
- 既存スタイル一覧は `styles/` を見る。新しいスタイルは `styles/<名前>.yaml` を1つ足すだけで増やせる。

## スタイル YAML のスキーマ

`styles/<名前>.yaml` は次のフィールドを持つ(値は日本語で可)。

```yaml
name: <名前>          # ファイル名と一致
用途: 何に使うスタイルか
トーン: 一言の方向性
配色:
  ベース: "#FFFFFF"    # hex で明示(放置するとクリーム/黄色がかる)
  文字: "#1A1A1A"
  アクセント: "#2563EB"  # 色数は2〜3に抑える
タイポ: 画像内文字の方針(入れる場合)
形式: フラット/線画/写真 などを1つに固定。影・グラデの乱用を避ける
余白構図: 余白・グリッド・整列の方針
サイズ: "比率・向きの指定。本文図は縦長〜正方形(横長は避ける)/ サムネは横長16:9(1280×670)"
prompt断片: >        # 補足の自由記述(任意・複数行可)
  ...
```

- note-figures は **スタイルの構造(トーン/配色/サイズ/形式…)をそのまま** codex に渡す(`render.sh --prompt <id>`)。
  各フィールドは日本語で可。**`サイズ` で向き・比率を必ず指定**(本文図=縦長〜正方形、サムネ=横長)。
- `prompt断片` は補足の自由記述(任意)。構造化フィールドがあれば無くてもよい。

## "AIっぽさ"を避ける指針(全スタイル共通)

放置すると安っぽく・テンプレ的になる。スペックで明示的に潰す。

- **配色を hex で必ず決める** — 放置するとクリーム色・黄色がかる。
- **余白とグリッドを指定** — 詰め込みが野暮ったさの元。ネガティブスペースを広く、整列。
- **形式を1つに固定** — フラット/線画/写真を混在させない。影・グラデ・装飾の乱用を避ける。
- **テンプレ感を避ける** — 各スタイルに固有の方向性を1つ持たせる(誰が作っても同じを避ける)。
- **キャラを描くなら画風を必ず指定** — 無指定だと生成ごとにランダムな動物・ゆるキャラが湧き、AI 丸出しになる。
  種別(人/役割)も固定し、毎回ブレないようにする。キャラ不要なら無理に出さない。
  ※**何が「AI っぽい」と感じるか・どの画風に逃がすか・キャラを出すか否か**は書き手の審美に属する判断なので、
  対象記事の **persona の「画像審美」**(`personas/<名>.yaml`)を見て決める(避ける画風・逃げ場・方向)。
- **技術名にはアイコンを添える** — 図にツール名(Tailscale / Caddy / portless / mise 等)が出るなら、その役割や
  定番イメージに合ったアイコンを prompt で**できるだけ指定する**(例: 証明書/HTTPS=鍵、表玄関=扉、振り分け=交通整理、
  VPN・接続=結ぶ線やノード、タスクランナー=再生/歯車)。無地のラベル箱だけだと識別しづらく、AI っぽい無機質さも出る。
- **図中の文字は日本語を基本に、英語の多用を避ける** — 記事が日本語なら図も日本語で揃える(英語ラベルを並べない)。
  プロンプトに「ラベル・文字は日本語で」と明記する。最小限の固有名詞・記号・単位は英数のままでよい。
- **画像内の文字は少なく大きく** — 縮小表示でも読める。長い文を詰めない(AI生成は日本語が崩れやすい→短く・少なく、崩れは目視チェックで拾う)。
- **ガチャ前提** — 指示は完璧には反映されない。同じ figure を**数枚生成して選ぶ**。日本語指示で十分。

## note 本文幅を意識する(本文図)

note の本文表示幅は狭い(**1行=全角で約34文字、約620px** 相当)。本文に貼った図はこの幅に縮小される。
**横長で要素を横に詰めると文字が極小になり読めない**(よくある失敗)。本文図は:

- **図も結論先出し**。いちばん大事な情報(結果・到達点・答え=「どこに何でアクセスできるか」等)を**図の上部**に置く。
  読者は上から見るし、縮小表示でも上は目に入る。経路・仕組み・理由はその下に積む。
- **縦並び・縦積みを優先**。要素を横に4〜5個並べるより縦に積む。
- **1図の要素を絞る**。多いなら複数図に分割する。
- **文字は大きく・少なく**。縮小後(本文幅=全角約34文字/行)でも読めるサイズを基準にする。
- 横長がどうしても要るなら**文字を入れない/最小限**にし、説明は本文テキスト側に書く。
- プロンプトに「note本文幅(約620px)で読める大きさ・縦構図で」と明記すると効く。

※ **サムネ(見出し画像)は別**。横長 1280×670 で広く表示されるので、この幅制約は本文図向け。

## スタイルの育て方

- 好みの既存画像・過去の良かった figure を LLM に読ませ、「この見た目を再現するスタイル定義(トーン/配色/形式/
  余白)を作って」と頼む → 生成 → ズレを手直し、を数回反復して固める。
- 固まったら `styles/<名前>.yaml` として保存。1記事ごとに見た目を育てていく。
- 各スタイル YAML 末尾にメモ用コメントを足し、「効いた/外した」知見を貯めてもよい。
