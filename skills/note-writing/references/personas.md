# persona(書き手の個性)のガイド(名前付き人格の仕組み・リビング)

記事の**声・人格を揃え、書き手らしさを保つ**ための名前付き persona の使い方。
**persona の実体はリポジトリ直下 `personas/<名前>.yaml`**(1ファイル1人格)。ここはその仕組みの説明。
画像の `styles/<名>.yaml`(image-styles.md)と完全パラレル。
最終更新: 2026-06-04(初版)。

## 参照のしくみ

- 記事の声は frontmatter の `persona: <名前>` で指定(`image_style` の隣)。
- 名前は `personas/<名前>.yaml` に対応(例: `persona: asagiri` → `personas/asagiri.yaml`)。
- **note-writing(執筆)も note-editor(レビュー)も同じ persona ファイルを源泉に参照する**。
  声を差し替えれば両方に効く。editor は渡された draft.md の frontmatter から persona 名を読む。
- 無指定なら既定 `asagiri` を使う(挙動が従来どおりになる安全側)。
- 既存 persona 一覧は `personas/` を見る。新しい人格は `personas/<名前>.yaml` を1つ足すだけで増やせる。

## 何を persona に置くか(一般原則との線引き)

> **persona = "どう聞こえるか"**(声・調子・温度・人称・敬体・好む/避ける言い回し・時制スタンス・距離感)
> **一般原則 = "機能するか"**(芯・構造・読者設計・スマホ・視覚設計・図・note仕様・タイトルの具体性)

一般原則は writing-craft.md(執筆)と editor-rubric.md(レビュー)に残る。persona には声だけを置く。
ai-generic(AIっぽさ回避)は、**"狩る手順・機構"は editor-rubric.md に残し、"何が自分にとってクサい/canned か・
温度の好み"は persona** に置く(機構は誰でも同じ、中身は人それぞれ)。

## persona YAML のスキーマ

`personas/<名前>.yaml` は次のフィールドを持つ(値は日本語で可)。

```yaml
name: <名前>            # ファイル名と一致
一言: その人らしさを一行で
敬体: ですます / である / 方針
一人称: 私 / 僕 など
温度・距離: 読者との距離、自虐や余白の出し方
掴みの癖: 好む導入(あるある自己同定 等)。決め台詞はテンプレ化しない
時制: 経験は過去形 / 記事全体で一貫
好む書き方: 体言止め・口語・体験の混ぜ方
避ける言い回し:        # AIっぽい/気取り。"リスト化しすぎない"も明記
  - 段取りの宣言(先に結論を見せます 等)
  - 中身のない定型(いかがでしたか / 実は / ぜひ / 〜していきましょう)
  - 気取り語(核 / 真髄 / 極意 / 〜の世界)・キメ顔の締め
noteらしさ: その人が書いた意味(体験/違和感/迷い)の出し方
判断の物差し: 声に出して読んで気恥ずかしくないか
画像審美:                # 画像生成の好み・嫌悪(image-styles.md=機能する原則 とは別に persona 側で持つ)
  避ける画風: 何が AI っぽく感じるか(例: ツヤ目・セル塗りソフト陰影の汎用アニメ顔)
  逃げ場: テンプレ顔に寄ったときに切り替える先(例: 顔なしピクトグラム/記号化シルエット、レトロ印刷)
  方向: クール / 温かい / レトロ など全体の指向
メモ: 効いた/外した知見(リビング)
```

- **固定の禁止語リスト化はしない** — それ自体がテンプレ化=クサさになる。物差し(声に出して気恥ずかしくないか)で都度判断。
- **画像審美**は文章の声と同じく書き手の主観なので、image-styles.md(機能する原則)とは別に persona 側で持つ。
  note-figures はこれを読み込んで、避ける画風・逃げ場・方向を生成プロンプトの方針に反映する。
- フィールドは増やしてよい。声・審美の差し替えで挙動が変わるよう、判断に効くことだけを書く。

## persona の育て方

- 過去の良かった記事・しっくりきた言い回しを LLM に読ませ、「この声の persona 定義(敬体/一人称/温度/避ける言い回し)を
  作って」と頼む → 生成 → ズレを手直し、を数回反復して固める。
- 固まったら `personas/<名前>.yaml` として保存。記事を書くたびに声を育てる。
- editor のレビューで「声から外れていた/守れていた」知見が出たら、persona の `メモ` に貯める。
- 記事ごとに別人格を使いたくなったら、新しい `personas/<名>.yaml` を足して frontmatter で指定する。
