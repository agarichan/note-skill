# note 仕様の要点(執筆に効くものだけ)

note.com のエディタは「完全な Markdown エディタ」ではなく、入力中に一部の Markdown ショートカットを
リッチテキストへ自動変換する方式。よって **書ける Markdown の範囲が限定される**。本文を整形するときは
ここで挙げた制約に合わせる。裏取り日: 2026-05-30。仕様は変わるので、疑わしければ実機で確認する。

## 見出し

- 使えるのは **H2 (`##`) と H3 (`###`) の2階層だけ**。`#`(H1)や `####` 以下は note では見出しにならない。
- 記事タイトルは note 側の別入力欄。本文の最上位見出しは H2 から始める。
- → 骨子は H2/H3 だけで筋が通るように設計する。深い階層が要る構成は分割を検討。

## 本文幅

- 本文の表示幅は狭く、**1行はおよそ全角34文字(約620px)**。長い1行・横長の図・幅広の表は収まりにくい。
- 図は本文幅で文字が潰れないよう **縦構図・文字大きめ**で作る(→ image-styles.md「note 本文幅を意識する」)。

## 強調・装飾

- 太字 `**〜**`(`__〜__`)。**日本語で記号が文字に密着すると効かない落とし穴**がある
  (CommonMark がスペース区切り言語前提のため)。例: `**「強調」**` が太字にならないことがある。
  → 太字の前後に半角スペースを入れる / 記号と本文の境界を空けるなどで回避。
- 取り消し線 `~~〜~~`。
- イタリックや文字色・インライン装飾は素の Markdown では当てにしない(エディタ機能側で行う)。

## コード

- コードブロックは ` ``` ` で囲む。**言語指定でシンタックスハイライト**が効く(```` ```python ````)。
- **インラインコード(`` `code` ``)は note 非対応**。バッククォートはそのまま literal で残る。使わない
  (代わりにそのままのテキスト、必要なら「」で囲む等で示す)。コードはコードブロックにまとめる。

## 数式

- **`$$ … $$` の LaTeX(KaTeX系)数式に対応**。技術・数理記事で有用。
- インライン数式の扱いは不安定なことがあるので、式は独立ブロックで置くのが安全。

## 表(テーブル)

- **Markdown のパイプ表(`| a | b |`)はネイティブ非対応**。素直には表を貼れない。
- 代替手段(優先順):
  1. **画像化** — 図メタブロックで `kind: 表` として画像生成に回す(本スキルの基本方針)。
  2. `$$ \begin{array}{...} … \end{array} $$` の数式ブロックで簡易表を表現。
  3. GitHub Gist に表を置いて URL 埋め込み。

## リスト・区切り・引用

- 箇条書き `-`、番号リスト `1.` は使える。**深いネストは崩れやすい**ので1段までを基本に。
- 区切り線 `---`(ハイフン3つ)。
- 引用 `>`。複数行は各行頭に `>`。note の引用は本文の下に**出典欄**を持つ。
- **引用の出典**を付けたいときは、引用ブロックの**直後**に1行で `<!-- cite: 出典テキスト -->` を置く
  (例: `<!-- cite: 山田太郎『書名』, https://example.com -->`)。URL はテキストとして併記する
  (出典欄はリンク化しない方針)。note-publish が `@@CITE:...@@` に変換し、引用の出典欄(figcaption)へ
  流し込む。**引用の直後以外に置かない**(prepublish が警告する)。出典が不要な引用には付けなくてよい。

## 埋め込み・画像

- **URL を単独行に貼ると自動で埋め込み**になる(YouTube / X(Twitter) / Gist / 各種カード等)。
- 画像はエディタへアップロードして挿入。本スキルでは図メタ → 画像生成 → 該当位置に挿入、という流れを想定。
- リンクは通常の `[text](url)` で可。

## 見出し画像(サムネ / アイキャッチ)

- 記事には **見出し画像**(記事上部・一覧・SNSシェア時に出るアイキャッチ)を設定できる。**本文の画像とは別枠**で、
  note の編集画面で設定する。本スキルでは **全記事で必須**(`figure: thumbnail` を本文先頭に置く)。
- 推奨サイズは **1280 × 670 px** 前後(横長)。文字を入れる場合は一覧・SNSでの縮小表示でも読める大きさにする。
- note には組み込みの「みんなのフォトギャラリー」もあるが、本スキルは図メタ → 画像生成で自前のサムネを作る前提。
- サイズ・仕様は変わりうるので、迷ったら実機で確認。

## 有料記事(ペイウォール)

note は記事を有料販売できる。**書く前に「無料 / 有料」と、有料なら価格・有料ラインの位置を決める**
(構成が変わるため)。構成側の作法は writing-craft.md の「有料記事の構成」を参照。

- **有料ライン**: 記事中の任意の段落に「— ここから有料 —」を1箇所だけ設置できる。
  ライン**より上が無料**(誰でも読める)、**より下が有料**(購入者のみ)。位置はあとから変更可。
- **価格帯**: 最低 **100円**。上限は会員種別で変わる(2026-05時点):
  - 無料会員: 〜**50,000円**(以前は1万円。引き上げ済み)
  - note プレミアム / note pro(法人): 〜**100,000円**
- **手数料**(売上から差し引かれる。実質手取りは概ね 80〜85%):
  1. 事務手数料(決済手数料): クレカ **5%** / 携帯キャリア **15%** / PayPay **7%**。購入者の決済手段で変動。
  2. プラットフォーム利用料: (売上 − 事務手数料) × **10%**(有料記事の場合)。
  3. 振込手数料: **270円 / 回**(売上を口座へ振り込む時)。
  - 例: 1,000円 / クレカ → 事務50円 + 利用料95円 = 145円差引 → 855円。さらに振込時に270円。
- **他の収益化**(必要時に調べる): 有料マガジン(複数記事をまとめ売り)、メンバーシップ(月額)、サポート(投げ銭)。
- 単価・上限・手数料率は変わりやすい。**金額を記事に書く/読者に案内する時は実機で再確認**する。
